1. Introducción a la Seguridad Ofensiva

¿Qué es la Seguridad Ofensiva?

Es un enfoque proactivo de la ciberseguridad que busca identificar, validar y demostrar vulnerabilidades mediante técnicas controladas, con el objetivo de reducir el riesgo antes de que un atacante pueda explotarlas.

Importante: Toda actividad de seguridad ofensiva debe realizarse con autorización, alcance y reglas de compromiso claramente definidas.

Objetivos de la Seguridad Ofensiva

  • Identificar vulnerabilidades técnicas.
  • Validar vulnerabilidades mediante pruebas controladas.
  • Evaluar y priorizar la severidad de los hallazgos.
  • Documentar evidencias técnicas.
  • Elaborar informes técnicos y ejecutivos.
  • Proponer medidas de mitigación y remediación.

Conceptos fundamentales

Vulnerability Assessment

Identificación y evaluación de vulnerabilidades.

Penetration Testing

Validación controlada de vulnerabilidades mediante técnicas de explotación.

Red Team

Simulación de adversarios para evaluar capacidades preventivas y de detección de una organización.

2. Marcos y Metodologías de Referencia

Los profesionales de seguridad ofensiva utilizan diferentes marcos, estándares y metodologías para estructurar sus evaluaciones.

OWASP ( Conceptual )

Open Worldwide Application Security Project
Comunidad y proyecto que proporciona estándares, metodologías, herramientas y recursos para mejorar la seguridad del software. OWASP Top 10, OWASP Web Security Testing Guide, OWASP ASVS, OWASP API Security Top 10

MITRE ATT&CK ( Conceptual )

Base de conocimiento de tácticas y técnicas adversarias
MITRE ATT&CK permite describir y analizar comportamientos utilizados por adversarios durante diferentes fases de un ataque. Tácticas, Técnicas, Subtécnicas, Procedimientos

ISECOM – OSSTMM (Técnico)

Open Source Security Testing Methodology Manual

Metodología orientada a estructurar pruebas y análisis de seguridad de manera sistemática y repetible.

Otros marcos de referencia

  • PTES – Penetration Testing Execution Standard
  • NIST SP 800-115 – Technical Guide to Information Security Testing
  • CIS Controls – Controles de seguridad
  • ISO/IEC 27001 – Sistema de gestión de seguridad de la información

3. Certificaciones en Seguridad

Las certificaciones pueden representar diferentes niveles de conocimiento y especialización.

Fundamentos

CompTIA Security+

Fundamentos generales de ciberseguridad, gestión de riesgos, controles y arquitectura.

Introducción al Pentesting

eJPT – Junior Penetration Tester

Orientada a fundamentos prácticos de pruebas de penetración.

Ethical Hacking

CEH – Certified Ethical Hacker

Formación orientada a conceptos y técnicas de hacking ético.

Seguridad de Aplicaciones Web

Burp Suite Certified Practitioner – BSCP

Evaluación práctica de habilidades relacionadas con seguridad de aplicaciones web.

Pentesting Avanzado

OSCP – Offensive Security Certified Professional

Certificación práctica orientada a pruebas de penetración y explotación controlada.

6. Análisis de Vulnerabilidades

El análisis de vulnerabilidades busca identificar debilidades técnicas y determinar su severidad, impacto y prioridad de remediación.

CVE

Identificador estándar para vulnerabilidades conocidas.

CWE

Clasificación de tipos de debilidades de software.

CVSS

Common Vulnerability Scoring System

Sistema utilizado para evaluar la severidad técnica de una vulnerabilidad.

El resultado debe interpretarse junto con el contexto del activo y el riesgo para la organización.

CVSS – Escala de Severidad

Puntuación Severidad
0.0 Ninguna
0.1 – 3.9 Baja
4.0 – 6.9 Media
7.0 – 8.9 Alta
9.0 – 10.0 Crítica

La escala debe interpretarse según la versión de CVSS utilizada.

Ejemplo de evaluación

Vulnerabilidad: Ejecución remota de código.

CVSS: 9.8

Severidad: Crítica

Acción: Priorizar la remediación y validar la corrección.

7. Documentación y Evidencias

Durante una evaluación se deben registrar las actividades, resultados y evidencias obtenidas.

Gestión de notas

CherryTree u otras herramientas de documentación.

Capturas de pantalla

Flameshot u otras herramientas para registrar evidencias.

Ejemplo – Instalación de herramientas

apt search cherrytree

Paquete de CherryTree.

apt search flameshot

Busca el paquete Flameshot.

sudo apt install cherrytree flameshot

Instala los paquetes seleccionados.

8. Informes de Seguridad

El reporte es uno de los entregables más importantes de una evaluación de seguridad.

Informe Ejecutivo

Objetivo: Comunicar los resultados a responsables de gestión y negocio.
  • Resumen ejecutivo
  • Alcance
  • Principales hallazgos
  • Riesgo general
  • Impacto para el negocio
  • Recomendaciones estratégicas

Informe Técnico

Objetivo: Proporcionar información suficiente para reproducir, comprender y remediar los hallazgos.
  • Descripción de la vulnerabilidad
  • Activo afectado
  • Evidencia
  • CVE / CWE
  • CVSS
  • Impacto técnico
  • Pasos de validación
  • Recomendación técnica
  • Referencias

Ejemplo de Hallazgo

Hallazgo: Servicio vulnerable expuesto a Internet

Activo: Servidor Web

Severidad: Alta

Evidencia: Servicio y versión identificados durante la evaluación.

Impacto: Un atacante podría aprovechar la vulnerabilidad para comprometer la confidencialidad, integridad o disponibilidad.

Recomendación: Actualizar el componente vulnerable y aplicar medidas adicionales de protección.
