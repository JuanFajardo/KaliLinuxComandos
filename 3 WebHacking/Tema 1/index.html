🌐 Fundamentos de la Web

¿Cómo funciona Internet realmente?
  • Red global de computadoras usando protocolos
  • Modelo Cliente-Servidor (petición → respuesta)
  • HTTP/HTTPS: texto plano vs cifrado
  • DNS: traduce nombres a IPs
  • Puertos típicos: 80 (HTTP), 443 (HTTPS), 3306 (MySQL/MariaDB)

    • 📡 Métodos HTTP y códigos de estado

    Métodos principales

    • GET → Obtener datos
    • POST → Enviar datos
    • PUT → Reemplazar recurso
    • DELETE → Borrar

    Códigos comunes

    • 200 OK
    • 301/302 Redirección
    • 403 Prohibido / 404 No encontrado
    • 500 Error interno

    ⚙️ Tecnologías Web Básicas

  • HTML: estructura de la página
  • CSS: estilos visuales
  • JavaScript: interactividad (y gran fuente de vulnerabilidades)
  • Backend: PHP, Node.js (corren en el servidor)
  • Bases de datos: MySQL, PostgreSQL, MariaDB

    • 🔍 Ver conexiones

    Las herramientas del hacker web
  • DevTools del navegador (F12) → Elements, Console, Network
  • BurpSuite → Proxy interceptador, Repeater, Intruder
  • Wappalyzer → detecta tecnologías
  • FlagFox → geolocalización de IPs

    • 🛠️ DevTools: Pestaña Network

    Navegador → [Petición GET/POST] → Servidor
    ← [Respuesta HTML/JSON/Imagen] ←
    📡 Desde Network puedes ver:
    - Método HTTP usado
    - Parámetros enviados (query string, formulario)
    - Cookies, cabeceras, respuesta del servidor

    🕵️ Proxy con BurpSuite

    Flujo típico:
    Navegador → (proxy localhost:8080) → BurpSuite → Servidor
  • Interceptar peticiones en vivo
  • Modificar parámetros (id, token, rol)
  • Reenviar con Repeater
  • Fuzzear con Intruder
    • 🔧 Configuración: proxy manual a 127.0.0.1:8080 + certificado HTTPS de Burp.

    ⚙️ OWASP Top 10

    Categoría OWASP Ejemplo de Ataque Descripción
    A01: Broken Access Control Cambiar el ID en la URL (/cuenta?id=101 a /cuenta?id=102) para ver datos ajenos. Acceso no autorizado a funciones o datos confidenciales de otros usuarios.
    A02: Cryptographic Failures Interceptar contraseñas en Wi-Fi pública porque la web usa HTTP sin cifrado. Exposición de datos sensibles por falta de cifrado o algoritmos obsoletos.
    A03: Injection Introducir código malicioso en un buscador para extraer la base de datos (SQLi). Envío de datos no confiables a un intérprete para ejecutar órdenes no deseadas.
    A04: Insecure Design Comprar productos con precios negativos porque el sistema no valida la lógica. Defectos arquitectónicos y fallos en el diseño inicial de la aplicación.
    A05: Security Misconfiguration Dejar la cuenta por defecto (admin/admin) en el panel de control. Configuraciones de seguridad incompletas, desactualizadas o mal gestionadas.
    A06: Vulnerable and Outdated Components Explotar un fallo público en un plugin antiguo y no actualizado de WordPress. Uso de librerías o componentes de software obsoletos con fallos conocidos.
    A07: Identification and Authentication Failures Un bot prueba millones de contraseñas filtradas (Credential Stuffing) hasta entrar. Debilidades al confirmar la identidad, permitiendo el robo de sesiones o credenciales.
    A08: Software and Data Integrity Failures Modificar un archivo de actualización en el servidor para distribuir un virus. Aceptación de código o datos sin verificar previamente su integridad o firma digital.
    A09: Security Logging and Monitoring Failures Un hacker extrae datos durante meses porque la web no registra accesos sospechosos. Falta de logs y monitoreo en tiempo real, impidiendo detectar o responder a ataques.
    A10: Server-Side Request Forgery (SSRF) Manipular un parámetro para obligar al servidor a extraer claves de su nube privada. Ocurre cuando la aplicación lee una URL remota sin validar el destino final.
