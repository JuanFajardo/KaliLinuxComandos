📂 Tema 1: Index Of

¿Qué es el "Index Of"?
  • Es una lista generada automáticamente por el servidor web
  • Muestra el contenido de un directorio sin una página index
  • Expone archivos que no deberían ser públicos
  • Ocurre cuando Options +Indexes está habilitado en Apache
  • Puede revelar: backups, configuraciones, código fuente, credenciales
    • ⚠️ Un "Index Of" mal configurado es una fuga de información crítica.

    🎯 ¿Dónde está en el OWASP Top 10?

    OWASP Top 10:2021

    • A01:2021 – Broken Access Control
    • A05:2021 – Security Misconfiguration

    Relación directa

    • A05 → Configuración insegura del servidor
    • A01 → Acceso no autorizado a recursos
    📌 Un Index Of es típicamente una mala configuración (A05) que permite acceso no autorizado (A01) a información sensible.

    🔧 Herramientas: Google Dorks

    intitle:"index of" site:ejemplo.com
    intitle:"index of" "parent directory"
    intitle:"index of" "backup"
    intitle:"index of" "config"
    intitle:"index of" "password"
    intitle:"index of" "db" | "sql" | "mdb"
    🔍 Los Google Dorks son consultas avanzadas que permiten encontrar directorios expuestos indexados por Google.
    💡 Ejemplo real: intitle:"index of" "parent directory" site:gov puede revelar documentos gubernamentales expuestos.

    💥 Tema 2: Fuzzing a directorios y archivos

    ¿Qué es el Fuzzing Web?
  • Técnica de fuerza bruta para descubrir rutas ocultas
  • Envía miles de peticiones con nombres comunes
  • Busca: /admin, /backup, /config.php, etc.
  • Identifica códigos de respuesta (200, 403, 301)
  • Puede encontrar paneles de administración, archivos de backup, APIs ocultas
    • Diccionario → [Petición GET /ruta] → Servidor
    ← [200 OK / 404 / 403] ←

    🎯 ¿Dónde está en el OWASP Top 10?

    OWASP Top 10:2021

    • A01:2021 – Broken Access Control
    • A05:2021 – Security Misconfiguration
    • A06:2021 – Vulnerable and Outdated Components

    Relación directa

    • A01 → Rutas administrativas sin protección
    • A05 → Directorios listados o mal configurados
    • A06 → Versiones antiguas con archivos expuestos
    📌 El fuzzing descubre recursos ocultos que pueden estar mal protegidos o ser vulnerables.

    🔧 Herramientas: DirBuster

    DirBuster → Interfaz gráfica (Java)
    Configurar: URL objetivo + diccionario
    Diccionarios comunes:
      • /usr/share/wordlists/dirbuster/directory-list-2.3-medium.txt
      • /usr/share/wordlists/dirb/common.txt
      • /usr/share/seclists/Discovery/Web-Content/
    🛠️ DirBuster es una herramienta clásica de OWASP para fuzzing de directorios y archivos.
    💡 También existen alternativas modernas como Gobuster, FFuf y Dirsearch.

    🔧 Herramientas: BurpSuite Intruder

    BurpSuite → Intruder
    1. Interceptar petición con Proxy
    2. Enviar a Intruder (Ctrl+I)
    3. Marcar posición de payload: §ruta§
    4. Cargar diccionario de rutas
    5. Iniciar ataque → Analizar códigos de respuesta
  • Sniper: un solo parámetro
  • Battering Ram: mismo payload en todos
  • Pitchfork: múltiples diccionarios en paralelo
  • Cluster Bomb: combinaciones de diccionarios

    • 🔓 Tema 3: .git Exposure

    ¿Qué es la exposición de .git?
  • El directorio /.git/ queda accesible públicamente
  • Contiene todo el historial del repositorio Git
  • Expone: código fuente, credenciales, ramas, commits
  • Ocurre por mala configuración del servidor web
  • Muy común en despliegues automáticos (CI/CD mal configurados)
    • ⚠️ Un /.git/ expuesto puede comprometer todo el proyecto.

    🎯 ¿Dónde está en el OWASP Top 10?

    OWASP Top 10:2021

    • A01:2021 – Broken Access Control
    • A05:2021 – Security Misconfiguration
    • A02:2021 – Cryptographic Failures

    Relación directa

    • A05 → Directorio .git mal protegido
    • A01 → Acceso no autorizado al código
    • A02 → Credenciales en texto plano en commits

    📋 Estructura típica de .git expuesto

    .git/
    ├── HEAD → Rama actual
    ├── config → Configuración del repo
    ├── index → Índice de archivos
    ├── logs/ → Historial de cambios
    │ └── HEAD → Referencias de commits
    ├── objects/ → Objetos Git (commits, árboles, blobs)
    │ ├── pack/ → Paquetes comprimidos
    │ └── info/ → Información de alternates
    └── refs/ → Referencias a ramas y tags
    ├── heads/ → Ramas locales
    └── tags/ → Etiquetas
    💡 Con acceso a .git/ se puede reconstruir todo el código fuente y su historial.

    🔧 Herramientas: DotGit y GitDump

    # Verificar si .git está expuesto
    curl -I https://ejemplo.com/.git/HEAD

    # GitDump - Reconstruir repositorio
    git clone https://github.com/Ebryx/GitDump
    cd GitDump
    python3 gitdump.py -u https://ejemplo.com/.git/ -o output_dir
    🔗 GitDump en GitHub
    🛠️ DotGit es una extensión de navegador que detecta automáticamente si /.git/ está expuesto.
